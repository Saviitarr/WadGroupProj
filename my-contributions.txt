Campus Connect - WAD621S Group Assignment 2026
Contribution summary - Backend / Database Lead

======================================================================
1. DATABASE
======================================================================
- Designed and wrote database/schema.sql: 7 related tables
    users, properties, rooms, property_images, bookings, reviews, contact
- Relationships (foreign keys):
    properties 1 - many rooms             (ON DELETE CASCADE)
    properties 1 - many property_images   (ON DELETE CASCADE)
    properties 1 - many reviews           (ON DELETE CASCADE)
    users      1 - many bookings          (ON DELETE CASCADE)
    users      1 - many reviews           (ON DELETE CASCADE)
    rooms      1 - many bookings          (ON DELETE RESTRICT - keeps booking history)
    contact has no foreign key, so visitors can send messages without an account
- Constraints as a safety net:
    UNIQUE email, UNIQUE student_number, UNIQUE (property_id, room_number)
    CHECK distance >= 0, capacity > 0, price >= 0, rating 1-5, end_date > start_date
    ENUMs for room_type, booking status and user role; role defaults to 'student'
- Wrote database/seed.sql: 1 admin, 3 students, 4 Windhoek properties,
  8 rooms, 4 bookings in different statuses, 3 reviews, 1 contact message

======================================================================
5. SECURITY MEASURES IN MY CODE
======================================================================
- Prepared statements for every query with user input (SQL injection)
- password_hash() / password_verify(), never storing plain passwords
- e() / htmlspecialchars on all output (XSS)
- require_login() / require_admin() checked on the server on every
  protected page - hiding links is not security
- session_regenerate_id() on login (session fixation)
- Server-side validation on every form (JavaScript can be bypassed)
- Role set by the database default, so users can't register as admin
- POST for every action that changes data; exit after every redirect
- Database constraints (UNIQUE, CHECK, foreign keys) as a last line of defence
